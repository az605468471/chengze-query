## 一、项目定位

**把散落在多个平台的数据聚合到一个页面，并标明每条数据的出处。**

### 核心价值：聚合 + 溯源 + 易用

懂行的人查一个币要开 5 个网站（BscScan、GoPlus、DexScreener、DefiLlama、Token Unlocks），
承泽查询把这些数据聚合到一个页面，且每条数据都标清楚「来源平台 + 获取时间」。

**不是「比 GoPlus 更权威」，而是「不用开 5 个网站，且知道每条数据从哪来」。**

## 五、开发中修复的 3 个坑

### 坑 1：CAKE 被判 F 级高危

**原因**：`is_mintable = 1`，但这是主流币的正常设计（抵押铸造）。
**修复**：GoPlus `trust_list = 1` 的代币走「主流币快速通道」，不从增发权限扣分。

### 坑 2：LP 锁仓误判

**原因**：主流币 LP 本来就不锁（有做市商、深度充足），锁仓主要针对小币防撤池。
**修复**：流动性 ≥ $1M 视为深度充足，不减分。

### 坑 3：持币集中度未排除黑洞地址

**原因**：CAKE 前 10 显示 97%，但第一地址是 `0x000...dead`（销毁地址，占94%）。
**修复**：评分时排除黑洞/销毁地址，CAKE 实际前 10 仅 3.17%。

## 七、技术实现

### 文件结构

```
czq-site/
├── index.html          # 单页应用（纯 HTML/CSS/JS，无 build）
└── js/
    └── query.js        # 查询引擎 + 五维评分
```

**为什么用纯 HTML 而非 React**：零 build、零失败风险、改完直接上线。

### 核心函数

| 函数 | 作用 |
|---|---|
| `getGoPlus(chainId, address)` | 拉 GoPlus 安全数据 |
| `getDexScreener(address)` | 拉 DexScreener 行情 |
| `getDefiLlama(symbol)` | 拉 DefiLlama 协议数据 |
| `analyzeHolders(goplus)` | 持仓分析（排除黑洞） |
| `analyzeLP(goplus)` | LP 锁定分析 |
| `calculateScore(...)` | 五维评分 |
| `queryToken(chainId, address)` | 主查询流程 |

### 支持的链

BSC(56) / Ethereum(1) / Base(8453) / Arbitrum(42161)
